# 手机局域网连接

`VoxPalmLinkNetwork` 是独立的网络适配库，依赖上一阶段 `VoxPalmLink`。当前还没有接入 App、手机扫码界面或系统按键投递。

## 配对

本人选择扫码为主、长码备用。`PairingInvitation.pairingCode()` 提供同一份二维码载荷/粘贴内容，包括随机 256 位密钥和随机设备标识。邀请五分钟有效，服务端同时使用单调截止时间；第一条通过 TLS 验证的连接消费邀请，停止邀请监听。失败需要重新生成邀请。

配对连接内生成新的独立长期密钥，客户端保存并确认后服务端返回完成消息。邀请密钥不会成为长期密钥。配对码不得写入日志、Bonjour TXT、URL 查询或分析事件；对象的普通/debug 描述均隐藏密钥。

`KeychainLinkCredentialStore` 使用本 App 的 service/account 命名空间，`WhenUnlockedThisDeviceOnly`，不云同步、不覆盖已有记录。删除失败会向调用方返回错误；配对失败回滚若遇到存储错误，调用方应通过设备管理清除残留记录。网络事务在断线瞬间不能保证两端原子提交：单侧留下未完成配对时，应撤销并重新配对。

## 加密与身份

当前限定 TLS 1.2 的 `TLS_PSK_WITH_AES_128_GCM_SHA256`，每个监听器仅配置一把凭据密钥。连接 ready 后再次核对协议版本、套件、应用协议和早期数据；禁用票据与会话恢复，拒绝证书回退。配对和控制使用不同的 PSK identity 域与 ALPN。

这条系统 PSK 路径已做实际回环对照，TLS 1.3 最小配置未握手成功；没有据此断言所有 Apple TLS 1.3 用法都不可用。TLS 1.2 专用 PSK AEAD 方案**没有前向保密**：长期密钥泄漏可能使历史网络录包失去保密性。未来升级到 TLS 1.3 双向证书绑定时需要重新验证，当前不声称已具备该能力。接口依据见 [Apple 工程师说明](https://developer.apple.com/forums/thread/711114) 和 [PSK 使用指导 RFC 9257](https://www.rfc-editor.org/rfc/rfc9257.html)。

Bonjour 只提供候选地址。服务名是随机凭据 UUID，配对服务 `_vp-pair._tcp`，控制服务 `_voxpalm._tcp`，不广播名字、密钥、录音或设备硬件标识。浏览到相同名字不能授予信任，仍需 TLS 密钥证明。

## 连接生命周期

- 启动是显式调用，关闭时调用 `stop`/`cancel`；不会自动启动本人正在运行的 App。
- TLS 握手/协议问候有期限，最多四个同时握手；发送积压最多 256 KiB，接收每次最多 16 KiB。
- 主机根据凭据绑定客户端身份，生成新的连接会话 UUID 并在 TLS 内发送问候。客户端从序号 1 开始发消息，每三秒发心跳；主机每秒检查上一层的期限。
- 断线、错误、超时、停止或撤销都交给 `LinkSession` 取消当前按住与录音；回调只输出意图，接入方仍必须遵守原有焦点/密码框/自动发送保护。
- `revoke` 先停止连接与监听，再删除持久凭据；删除失败返回错误，不能把 UI 显示为已永久撤销。
- 网络接口均由主执行器串行操作。重连使用新客户端实例，旧连接回调不能操作新会话。

## 接入和验证边界

Mac/iPhone App 接入时还需声明本地网络用途和两种 Bonjour 服务，并实现真实授权失败提示、二维码界面和可信设备列表。库本身不申请用户权限，也没有替运行中的 App 添加能力。

回归测试用回环监听和内存凭据存储，验证真实 TLS、错误密钥、用途隔离、密钥轮换、存储失败、消息传递和撤销取消。没有写用户钥匙串，没有局域网广播或采集声音。真实同网发现、扫码、钥匙串和跨设备稳定性仍需 App 接入后的验收。
