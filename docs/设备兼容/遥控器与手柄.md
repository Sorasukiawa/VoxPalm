# Siri Remote、DualSense 与 DualSense Edge

状态：源码已加入适配，DSE 的 23 个按键输入、八方向及回中已分别通过 USB 和蓝牙实物验证；USB 内置麦克风配合 R1，以及蓝牙 R1 配合 Mac 麦克风的中文转写和聊天框贴字均已实测（见下方记录）。手柄蓝牙收音仍在实验，整款设备验收尚未完成，也尚未包含在 beta.2 下载包中。报告解析单测、模拟输入和界面截图不能代替真实设备测试。

|---|---|---|---|

| Siri Remote 第二、三代（A2540 / A2854） | 蓝牙 HID | 型号识别、银色方向环外形、逐键学习、单击/双击/长按 | 真机按键与松开；方向环只指实体按下，滑动触摸、内置麦克风未接入 |

## DSE 输入实测（2026-10-25）

单台 DSE 在 macOS 27.0.1 上分别通过 USB 和蓝牙测试，收到 USB 64 字节及蓝牙 `0x31` / 78 字节完整输入报告，蓝牙 CRC32 校验通过。基础输入测试直接使用本项目的原生 HID 读取和按键解析代码，不执行动作；App 说话与贴字的独立实测见下一节。

- 已逐项收到按下和松开：□、△、○、×、L1、R1、L2、R2、L3、R3、创建、选项、触摸板按下、静音，共 14 个普通键；左右 Fn 和左右背键也已分别确认。
- PS 键也收齐按下和松开；十字方向键的四个正方向、四个斜方向和松开回中全部正确，斜方向同时解释为相邻两个方向。这台手柄的 23 个按键输入均已取得真机记录。
- 原自定义配置中，左右背键被设置成 × / ○，输入只表现为 × / ○。按 Fn + △ 切到默认档后，能独立读取左右背键。配置不同会改变实际报出的按键，不能默认所有配置都能区分背键和正面键。
- 同一连接的后续按住复测：左背键 2.61 秒、右背键 2.89 秒、R1 2.66 秒，按下和松开收齐，期间未断线；之后上述 14 个普通键的短按窗口也未断线。
- 蓝牙下分别实测 ×、左右 Fn、左右背键及 R1 按住约两秒；其余普通键、PS、八方向和回中也逐项到达，23 个键全部收齐按下 / 松开。本轮没有断线、残留按住或校验拒绝。此连接使用持续报告流，没有验证无流时的查询回退。
- 较早的测试曾发生三次底层 USB 硬件连接丢失，系统内核与读取工具的设备移除记录一致；线材、接口或其他链路因素的具体原因尚未确定。后续短时复测没有复现，不代表长期稳定性通过。
- 尚未验收：无流查询回退、长时连接稳定性、双击动作、按住时断线取消与重连恢复；DS5 和 Siri Remote 的真机测试仍未完成。

## DSE 蓝牙说话与贴字实测（2026-10-25）

- 使用独立配置的原生 App，只绑定 R1 长按说话，收音明确选 Mac 内置麦克风，使用系统内置转写（`zh-CN`），自动发送关闭。
- 真人按住 R1 说话、松手后停止：日志确认开麦为 `MacBook Pro Microphone`、48 kHz、单声道，先后两次录音约 4.1 / 4.9 秒，中文转写成功。最初仅将结果写入测试文件，因此这两次不能算贴字通过。
- 取消仅写测试文件的调试设置后，再次真人按住 R1：录音约 5.5 秒，转写约 0.5 秒，输出 11 个字；本人确认文字自动填入当前聊天输入框。该测试窗口内没有设备断开或按键残留。
- 本节验证的是手柄按键控制加 Mac 麦克风收音。当前这台 Mac 的蓝牙连接下，系统音频输入清单未列出 DSE，手柄蓝牙收音尚未通过；自动发送也未验证。

## DSE USB 内置麦克风实测（2026-10-25）

- 同一只手柄用 USB 数据线直连 Mac，耳机孔未接设备，系统列出 DSE 的 48 kHz、双声道音频输入。指定该输入的约五秒采样接近 48,000 帧/秒，有实际声音，系统默认输入仍是 Mac 麦克风。
- 在掌声收音设备中明确选择 DSE 的 USB 输入，只绑定 R1 长按说话，内置中文转写和自动贴字开启，自动发送关闭。本人对着手柄按住说话；日志确认开麦 `DualSense Edge Wireless Controller`、48 kHz、双声道，录音约 3.6 秒、转写约 0.2 秒，输出 12 个字，本人确认文字自动填入聊天框。
- 本机验证的是 USB 下手柄自身收音。蓝牙音频短时探测能得到可解码数据，但当前读取路径有明显缺帧，尚未接成可用的蓝牙收音功能；不能把 USB 的结果算作无线麦克风通过。
- 蓝牙音频与按键共用报告编号，已增加音频分流，音频数据不会被当成按键或全部松开。音频启用、解码与低层通道探测仍留在独立实验程序，没有把未通过的蓝牙收音入口放进 App。

## 使用

1. 先通过 macOS 蓝牙设置连接遥控器或手柄，手柄也可以用 USB 数据线连接。
2. 掌声「设置 → 设备」里选择对应设备。手柄列在「游戏手柄」里；同型号手柄在能取得硬件身份时按各自身份保存选择，不靠同名归并。
3. Siri Remote 在「设置 → 按键」点图上的键，再按实物同一键学习。各代和系统暴露的 HID 用途可能不同，无法收到的键不能宣称支持。
4. 手柄不用学普通按键。可套用「AI 编程」预设：方向上/下切对话，R1 长按说话，叉键发送。Siri Remote 的 Siri 键学好后也能设成长按说话。
5. 蓝牙手柄被选中后，掌声读取一次校准 Feature Report，请它提供完整输入；查询失败时保留基础输入。识别设备那一步不发送这个查询。不会写入固件、板载键位或灯光/震动配置。
6. 蓝牙原始报告流超过 0.25 秒没有数据时，在后台最多每秒查询 30 次输入报告；报告流恢复就停止查询，查询失败则降到每秒一次。取消选择、断线和停止监听会让在途查询失效。这个回退同样需要真机验证。

掌声采用共享监听：前台游戏和系统仍可能收到同一次按键。玩游戏时请暂停掌声监听。Siri Remote 的电源键可能锁屏或睡眠，不建议映射；音量、播放键也可能同时执行系统动作。当前没有宣称这些键已被独占拦截。

断线、换设备或停止监听时取消未完成手势；尚未松手的内置录音丢弃，不自动贴字、发送。松手后已经开始的转写或延迟回车仍按原流程完成。外部输入法会收到结束按键，但其已识别文字如何处理由输入法决定。没有稳定硬件身份的设备使用当前连接编号，重连后可能需要重新选择。

## 实物验收清单

- 记录型号、固件、macOS 版本及 USB/蓝牙连接方式。
- 先确认蓝牙原始流或查询回退确实收到数据，再测按键；系统控制器会话可能影响报告流，解析单测不能验证这一点。
- 每个可用键分别按一下、双击、按住再松手，确认界面只亮一个对应键、没有重复动作。
- 手柄方向键测八方向及回中；Edge 的两个 Fn、两个背键分别验证，并记录板载配置。
- 用 R1 或已学的遥控器键按住说一句，确认使用的是选定的麦克风，松手停止。
- 按住时断开、取消选择和暂停监听，确认录音停止、不误发送、不补发单击。
- 重新连接后再测一次；同型号两台同时连接时确认选择不会串台。
- Siri Remote 要分别记录能学到与收不到的键；触摸滑动不计为本次已支持能力。
