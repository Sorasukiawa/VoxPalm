# 手机通信协议 v1

当前实现是 `Packages/VoxPalmLink` 的独立消息协议与接收状态机，未接入运行中的 App。没有网络监听、配对码验证、密钥保存、手机界面或实际输入投递；下面的字节格式只能用于已经认证并加密的连接，不能在明文网络上承载声音或控制指令。

## 身份与调用边界

- `requestPairing`、`confirmPairing` 只表示本机确认的信任状态；它们不提供密码学认证，不是远端可发送的消息。
- 网络层必须先验证对方身份，再调用 `connectAuthenticated(peer:)`。`peer` 来自身份验证结果，不能直接相信包里的 `deviceID`。
- 连接成功返回新的 `sessionID` 和 `transportID`。前者应通过已认证的握手告知对方；后者只在本机使用，绑定到这条真实连接的接收/关闭回调，不上网。具体握手与 TLS 接入尚未实现。
- 对每个受信任对端串行持有一份 `LinkSession`。旧连接不能替换在线连接，必须先结束；重新连接时生成新会话并把序号重置为 1。
- 调用方按返回顺序执行 `LinkEffect`，在接受下一批事件前处理取消效果。不得把 `cancel` 当成正常 `up`、单击、音频结束或发送指令。未来 Mac 接入还需遵循原有按键映射、焦点、密码框与出字保护。
- 调用方定期执行 `checkTimeout`；本包没有后台任务。默认 10 秒没有完整合法消息即断开，建议网络层每 3 秒发送心跳。不完整消息不能续期。
- 撤销时除了调用 `revoke`，网络层还要删除自己持有的可信设备记录。这个包没有 Keychain 或持久化代码。

## 分帧与消息头

整数字段统一使用大端（网络字节序），只有音频样本用小端。UUID 使用 RFC 形式的 16 个字节，顺序对应字符串去掉连字符后的十六进制，不使用语言对象的内存布局。

每帧以 4 字节 UInt32 消息体长度开头，不包含这 4 字节本身。消息体最大 65,536 字节，零长度拒绝。`LinkSession.receive` 直接接收带长度前缀的流片段，每次最多 16,384 字节；可拆开一帧，也可包含多帧。网络适配应据此限制单次读取大小。

| 消息体偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 2 | `protocolVersion`，固定 1 |
| 2 | 16 | 已认证发送设备的 `deviceID` |
| 18 | 16 | 当前连接的 `sessionID` |
| 34 | 8 | `sequence`，从 1 开始连续增加 |
| 42 | 1 | 消息类型 |
| 43 | 按类型 | 消息载荷 |

不接收序号 0、重复、回退或跳号；达到 UInt64 上限后不能绕回 0，应建立新连接。未知版本/类型、截断、尾随字节、无效字段会使连接结束，不尝试从损坏的流里重新寻找边界。

## 消息载荷

所有载荷字段按表中顺序排列，没有隐含填充或可选字段。长度字段后的数据必须恰好满足长度；一条消息后多出的任何字节都拒绝。

| 类型值 | 名称 | 载荷 |
|---:|---|---|
| 0 | `heartbeat` | 无 |
| 1 | `button` | UInt8 标识字节数、UTF-8 标识、UInt8 phase |
| 2 | `pointer` | UInt8 子类型，后接对应字段 |
| 3 | `audioStart` | 16 字节录音 UUID、UInt32 采样率、UInt8 声道数、UInt8 编码 |
| 4 | `audioChunk` | 16 字节录音 UUID、UInt32 块序号、UInt16 PCM 字节数、PCM |
| 5 | `audioEnd` | 16 字节录音 UUID、UInt32 总块数 |
| 6 | `audioCancel` | 16 字节录音 UUID |

按键标识限定 1～64 个 ASCII 字节，只允许字母、数字、`-`、`.`、`_`，表示用户配置中的动作槽位，不是系统键码或脚本。phase 的 1/2/3 分别表示 down/up/cancel。重复 down、没有对应 down 的 up/cancel 均拒绝；最多同时按住 16 个普通按钮。

指针子类型 1 为 move、2 为 scroll，各带 x/y 两个 IEEE 754 Double，其 64 位比特按大端编码。坐标必须有限且绝对值不超过 4096；单位转换与实际投递由后续适配层决定。子类型 3 为鼠标按钮，载荷是 UInt8 按钮（1 主键、2 副键、3 中键）和 UInt8 phase。每种鼠标按钮也必须成对开始/结束。

## 音频与资源限制

- 编码 1：单声道有符号 16 位小端 PCM；仅接受 16,000 或 48,000 Hz。编码/格式在 `audioStart` 固定，中途变更必须取消后重新开始。
- 每块非空，字节数是 2 的整数倍，最多 40 ms：16 kHz 为 1280 字节，48 kHz 为 3840 字节。块序号从 0 连续增加。
- 每条连接同时只有一轮录音；`audioEnd` 的总块数必须与接收数相同，少块、错录音 UUID、重复开始都会取消当前录音并关闭连接。结束空录音允许总块数为 0。
- 每轮音频时长最多 300 秒，实际经过的单调时间也最多 300 秒；心跳不能延长这项上限。样本预算超出时，超出的块不交付。
- 每条连接最多使用 256 个不同录音 UUID，已用 UUID 不得复用；达到上限后重新连接。状态机只存计数和 UUID，不保存整轮声音。
- 调用方必须及时消费输出，后续音频队列也要有自己的上限；本包有界分帧不等于整条 App 音频链路都有内存上限。

## 断开与错误

断线、撤销、协议错误或超时会依次输出普通按键 cancel、鼠标键 cancel、录音 cancel，再在需要时要求关闭传输。不会合成单击、音频 end 或自动回车。断开前已完整结束的输入不重复取消。

每次网络 EOF 都要调用 `disconnected(transportID)`，半帧 EOF 会作为截断收尾；其他传输错误调用 `transportFailed`。旧 `transportID` 的消息、错误和断开事件都被忽略，不刷新当前连接期限，也不取消新会话。

配对状态包括未配对、等待确认、已配对、已连接、重连中、已撤销。协议失败进入重连中，但新连接仍必须重新验证传输身份；撤销后不能直接重连，必须重新获得本机确认。

## Mac 到手机的语音状态

已验证的同一 TLS 连接在 40 字节会话问候之后，可以发送语音反馈帧。仍使用四字节大端长度；正文固定 74 字节：版本 1（1 字节）、会话 UUID 的 ASCII 字符串（36 字节）、录音 UUID 的 ASCII 字符串（36 字节）、状态（1 字节）。接收端检查长度、版本、会话和已知状态；手机界面还检查当前录音 ID，不处理旧轮次反馈。

状态按值 1–11 依次是：accepted、transcribing、finished、copied、tooShort、noText、cancelled、failed、busy、requiresBuiltIn、unavailable。反馈不带音频、转写文本或系统错误详情。旧 Mac 不返回 accepted 时，手机等待超时取消，不能凭连接就开始收音。

App 对完整 `audioEnd` 后尚未完成的转写继续保留设备绑定；发生可观察的断开、撤销或关闭连接时取消它。取消不能撤回已经完成的输入投递，不能用协议层的“录音已结束”推断“转写已完成”。

## 验证边界

本包测试只使用内存数据，覆盖固定字节样本、分片/合并、逐字节变异、身份/会话/序号拒绝、连接生命周期、音频连续性和资源限制。平台编译或这些测试通过都不代表真实配对、加密、手机收音、触控板投递或真机兼容已经完成。
